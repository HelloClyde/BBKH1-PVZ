# 第三关连续游戏退出：定位与验证（2026-11-15）

用户反馈从第一关连续玩到第三关，在收集阳光或种植时退出。调试使用 ESP32 0.4.5 经 `esp://COM6` 连接 H1Debug；现有五个存档已只读备份并整目录保护，测试使用独立玩家。

## 已复现的故障

诊断版 `509fbab8…` 通过真实触摸打完第一关、第二关并进入第三关，第三关更新计数 7360、5 株向日葵时，在收阳光后异常退出，返回码 107。第二关曾因测试脚本遇到调试输入忙而中断、无人操作失败，随后在同一 BDA 进程正常重试并通关；没有重启进程、直接改游戏 RAM 或写入获胜结果。

保留 RAM 证明：`Invalid offline actor page` 来自 `sunflower-glow.h1ap` 第 117 页，4,096 字节分配失败，尚未开始本页解压。堆共空闲 246,308 字节，但最大区域仅 34,796 字节，且是原生 SDK 所需的尾部空间。退出前应用原生跨度峰值 22,498,372 字节。旧版故障日志也有混音器不必要的 98,340 字节连续分配失败。这些数据证明了内存压力和碎片，不能据此认定所有前两关对象都泄漏。

证据：`build/level3-crash-20261115/chain-52.json`、`chain-retained-failure-details.json`、`chain-play.log`。本次极端不足时旧故障写入器留下零字节文件，RAM 证据已另行保存，未把零字节文件当成有效故障记录。

## 修复

- 预览与实际游戏使用同一个 Board，但图片借用必须按阶段结束。进入游戏时先结束预览阶段对 Board 图片的持有，再准备实际游戏帧；存活动画和共用 UI 保留其各自引用。
- 原完整流程第三关图片约 2.24 MB；离线对比确认清理预览图片并准备实际帧后约 0.93 MB，480×272 画面逐像素一致。修复后的自然预览/开局探针约 1.04 MB，实际帧再次准备后 0.93 MB。
- H1 音乐按当前采样率、声道数和已有最坏节拍公式申请缓冲，去掉历史高采样率立体声的最低尺寸。16 kHz 单声道两块缓冲从 147,510 字节降至 24,000 字节。
- 故障信息在清理前冻结，待应用内存返回后再写入，避免写故障记录本身又因内存不足失败。正常帧和正常退出不写此文件。

## 已通过的离线检查

- 实际植物读取器 50 类、200 个动画库、9,744 次画面对比一致（诊断改动）。
- 音频 7 组、50,400 个 PCM/节拍状态块与原库完全一致；额外检查 12 组采样率/声道/格式边界。
- 修复后 40 株植物、40 次稳定画面比较、3 次选项往返，无稳定帧图片重载或自动淘汰。
- 故障写入器 7 类检查，包含清理前快照保持、旧记录读取和 GBK 路径。
