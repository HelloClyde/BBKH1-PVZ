# H1 平台移植说明

引擎固定为 `UPSTREAM.json` 中的 PvZ-Portable 提交。构建复制原源码后应用有上下文校验的补丁，原 `upstream/` 保持不变。Lawn 的植物、僵尸、关卡、胜负、奖励和 v4 存档流程参与实际编译。

## H1 离线适配模式

H1I2 用独立的逻辑宽高和存储宽高保存缩图，H1X2 索引同样区分两者；旧 H1I1/H1X1 保持兼容。游戏、动画轨道、字形指标和输入仍使用 800×600 坐标。渲染直接读取物理尺寸 ARGB 缓存，原 GetBits 兼容入口才按需展开逻辑像素。

2448 张图像按 9/20 离线缩放，RGBA 在预乘透明度空间滤波；帧格和字形分别过滤，物理边界按同一 floor 规则映射并限制采样，避免相邻帧串色。32 张存在非整除帧格、重叠或零像素字形、透明网格依赖的图片保留原样，原因列在资源清单。原 XML、字体指标、音频和关卡规则保留。

启动时依据缩图资源固定模式，尚无图集的动画沿原无图集分支绘制，避免再生成逻辑尺寸大图集。物理屏幕模式保留 800×600 的逻辑 GLImage，实际绘制及呈现为独立 360×270 MemoryImage；屏幕操作统一变换坐标和裁剪，离屏对象不变。意外原始 GetBits 会生成原步长快照并永久固定到兼容大画布，正常菜单及游戏验证中该回退计数为 0。

原生菜单的收益来自缩小常驻工作集、消除反复读图，以及把实际绘制像素减少到约 20%。当前物理画布通过原三角形采样绘制；另外验证过的不透明行拷贝快路径用于保留大画布的缩图模式，不把它冒称为物理模式的实际路径。

调用栈仍为 128 KiB，只放有界临时缓冲；贴图、画布和对象仍使用固件共享堆。SDK 没有已验证的额外大栈/RAM申请接口，静态栈预留不会增加共享堆总容量。

## 平台接口

| 部分 | H1 实现 |
| --- | --- |
| 窗口与输入 | V1.41 普通 BDA 服务；触摸和键盘传入原 WidgetManager |
| 绘图 | 原 MemoryImage/SWTri 加软件后端，逻辑画布 800×600，LCD 等比显示 362×272 |
| 资源 | 原尺寸 H1I 图像、原 XML 动画与字体指标；元数据索引减少 FAT 查找 |
| 声音 | 原音效流式读取；libxmp 播放完整 XM，混音输出至 H1 PCM 接口 |
| 文件 | 先探测 A:\应用\数据\游戏\PVZ，再探测 B 盘同目录；资源、userdata、缓存和日志共用选中根目录 |
| C/C++ | GCC 15.2、Newlib、完整 hosted STL、异常处理及 RTTI；原生调用桥接 |

V1.41 中断会覆盖 `$gp`，所以程序与运行库统一采用 `-G0`，去掉 Newlib 强制的 `.sdata` 属性。构建审计实际目标文件及运行库的 GP/GOT/CALL/LITERAL 重定位、TLS 和地址边界。GCC 的传统 `.ctors` 表也会保留并执行。

## 内存管理

固件公共堆为 32 MiB，由系统和应用共同使用，不能把模拟器的 64 MiB 总 RAM 当作应用可分配空间。

V1.41 的原分配器在搜索空闲块前要求尾部至少还有 8 字节管理记录空间，可能出现空闲数 MiB 却拒绝小额请求的情况。运行库按原分配器的首次适配、切分及尾部追加规则保护余量：新的尾部数据追加须留下 64 KiB；已有空闲块的切分每次只花 8 字节，可以继续使用管理记录空间，但须留下 8 KiB。必要时整块复用已有空闲记录。整块路径核验关键固件指令、堆界与全部记录，持有原分配信号量，只设置选中记录的使用位；释放仍交给原固件。它不移动对象或修改固件代码。

这两个余量是本应用的保护策略，不代表其他固件线程的任意分配都有保证。整块复用可能带来内部浪费，因此另外记录实际原生块长度和诊断计量；用户请求字节数不等同于固件占用字节数。

- 实体容器按 32 槽位惰性分配，保留原容量、编号、遍历顺序和稳定地址。
- 全局辅助对象池按约 4 KiB 的批量首次初始化，大对象至少一项，小对象最多 16 项；不足时继续增长。真实屏幕根绘制前仅释放存活计数为零的整池块，保留池身份和配置。
- 字体加载结束后，将解析树保留为相同 GetDefine 文本，字形、字距和图层继续使用原已编译数据。
- 相同乐谱轨道逐字节去重；主旋律和鼓点共享只读数据，各自保留播放、跳转和声道状态。
- 原动画 XML 直接解析为完整定义，省去读写编译缓存时的整块复制与解压峰值。
- 原动画 XML 首次解析成功后，将轨道和帧数组收缩到实际长度，再补齐缺省数据和构建图集。所有帧值及图片、字体、文字指针原值均保留，不迁移已发布或正在播放的数组。
- 进入棋盘后，仅在菜单控件及全部动画实例（含待删除实例）均不再引用时，卸载 SelectorScreen 定义。字符串所有权在 XML 继承补齐前固定捕获；释放后完整重置定义，回菜单时仍由原加载器重建。加载过程和演职员表期间禁止此项回收。
- 原文件图片按需载入；修改后的图片和动态目标不作为可回收文件缓存。
- 仅含透明度的字体图片在正常或叠加绘图选择源缓冲前，按原 8 位透明度索引和 256 项颜色表加载。颜色表使用图片原有的合成 RGB，不改字形或透明度。已展开、修改、特殊透明网格及自绘图像不转换；缩放等泛用 GetBits 路径仍按原方式展开。不能在绘图已借用裸指针后替换源缓冲。
- `data/` 中不可变的 RGBA 字体还可尝试完整颜色索引：流式核对实际文件，最多保留 256 个原始 ARGB 值，连透明像素的 RGB 也不改变。遇到第 257 种颜色即释放临时数据并记住索引拒绝结果；较小图片继续原 ARGB 路径，大型字体可使用下述分页。它不适用于 RGB 标题图，也不把彩色字体当作单通道透明度。
- 大型渐变 RGBA 字体可保留完整 ARGB 小页，在正常或叠加绘图前把已裁剪字形复制到小图，再调用原绘图函数。这样不需要整张字体的大块连续缓冲和派生数据；原颜色、混合公式和源图透明标志均保留。泛用 GetBits 仍先释放分页，再按原方法展开。
- 大型 RGBA 三角形贴图可通过页视图读取原采样点，保留 SWTri 的坐标、无符号边界判断、双线性权重与混合公式。菜单图回收后重载时，在三行小缓冲上调用记录的原透明边缘平均函数，恢复原像素；首次加载和 RGB 标题图仍保留原行为。
- 大型、无透明度的 RGB 文件在整数坐标、白色正常绘制到不透明屏幕时，保留原 RGB24 字节为 3072 字节分页，按跨度逐行还原 ARGB。原尺寸、坐标和每通道 8 位值不变；泛用 GetBits 路径先释放分页再按原方式展开，避免两份同时占用。
- 只有确认同步绘图已结束的批次才推进像素使用边界。压力回收保留当前批次的裸像素指针；离屏与嵌套绘图受保护。
- 泳池前的背景绘制、泳池各组三角形完整返回后另设窄边界，允许回收已完成使用的纹理；仍保留原三角网格、取样、透明度和水面动画。
- 压力回收每次只释放一个合适的旧源图片，随后实际重试固件分配；成功即停。可回收总字节数不代替连续内存分配结果。
- 没有任何实例引用的动画贴图可在真实屏幕根绘制前或帧结束后释放，再由原图与原构建器重新生成；仍保护 holder 中待删除的实例，离屏和嵌套绘制不触发前置回收。

分页阈值为 800000 像素，覆盖 1400×600 关卡背景。800×600 标题保持原 ARGB/RL 路径：原生对照发现，标题改成小页会改变后续菜单大块分配的复用布局，引起持续回收和读图；恢复标题路径后菜单压力回收归零。因此不能只依据单个图片更省内存就扩大分页范围。

## 验证范围

`build/host/verification.json` 记录完整原程序的主机集成测试，包括第一关四波、实际伤害、暂停恢复、奖励、第二关和 v4 存档复开。主机测试的逻辑时钟加速明确写在报告中，不能用来证明 H1 实时性能。

字体、图片、乐谱共享和绘图回收另有逐字段、逐像素及逐 PCM 样本对照。物理 H1、固件模拟器、主机测试分别记录，不能相互替代。固件验证只通过原生按键和触摸操作游戏，GDB 仅用于只读观察；没有注入阳光、实体、进度或存档。

实际交付构建以 BDA SHA-256、对应 `.build.json` 与固件场景报告为准。SDK 的固定中文路径使用 GBK 字节，内部虚拟 /PVZ 和 /PVZSAVE 均映射到同一选中根目录。模拟器只提供 NAND/A 盘，因此 B 盘选择逻辑有独立桥接测试，B 盘实卡仍需实体设备验证。
