# 资源生命周期修复（2026-11-15）

对应静态审查 `resource-lifetime-static-audit-20261115.md` 的四项问题。

## 修复

- 保存队列：扫描、认领及已完成任务摘除都在同一个关中断临界区完成。任务分配、实际释放和所有文件操作均在锁外，保存线程不调用应用分配器。
- 完成回收：前台普通帧服务在处理前后回收已完成任务，停止依赖下一次存档、文件查询或退出才回收。
- 领奖光效：离线 v5 目录可直接定位已烘焙的独立 LZ4 帧，不再启动整包展开。常驻目录、调色板、最大压缩帧输入区和两块解码工作区；加载阶段预热两种效果的首帧，领取点击不分配内存也不读文件。保留原 600 tick 时序和原有画面。
- 领奖页：在 Board 已销毁、绘制借用已结束后释放战斗动画库和草坪数据；保留卡片预览实际使用的 CachedFrames。

H1 的 newlib 使用 `-Os` 构建，其无缓冲 `fread` 缺少直接读取用户缓冲区的快速分支。因此最终实现使用 `open/read/lseek/close`，直接走已有的原生分块文件接口，避免逐字节 SD 读取。文件描述符随当前 Board 生命周期释放。

## 代价与范围

奖励效果的已烘焙帧字节完全保留；取消外层整包压缩，磁盘文件由 934,748 字节变为 1,220,539 字节，增加 285,791 字节，换取约 1.20 MB 的战斗堆内存减少。运行资源共 2,674 个文件、166,759,394 字节。运行中不做资源 CRC；构建和安装传输仍核验完整性。

- 主机真实双线程：20,000 个任务，FIFO 和首帧删除门控正常；认领中任务不被释放；完成数据由普通帧回收；分配器只在前台调用，且不在临界区。
- 主机真实文件：短写、打开失败、关闭失败、安装失败均保留原存档；中断备份恢复和相同内容跳过通过。
- 完整游戏主机构建：212 帧 × 6 种位置/裁剪条件，共 1,272 张画面与已接受的 v4 解码及绘制代码逐像素一致；常驻工作区 55,708 字节；真实粒子首帧无文件读取、时钟保持、领奖预览可绘制，领奖阶段战斗库和草坪归零。
- 原生候选：194 个源文件构建及 GP/TLS 审计通过。真机验证完成：第三关自然结束及完整领奖、同进程第四关/选项/返回菜单、创建与删除测试玩家均通过；分配失败和保存错误均为 0。

证据目录：`verification/resource-lifetime-20261115/`。详细现场日志和冻结 ELF 位于本地 `build/resource-lifetime-fix-20261115/`、`build/resource-lifetime-v81-r2-native/`。
