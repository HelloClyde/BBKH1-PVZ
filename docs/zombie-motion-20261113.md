# 第一关僵尸停住：修复与真机验证

真机原问题是：关卡和僵尸的更新计数持续增加，僵尸本体动画速率却为 0，动画时间与位置都不再变化。冻结、黄油和关卡暂停均未生效；移动所依赖的 `_ground` 轨道和速度数据正常。最早将速率归零的具体调用点尚未证实。

`platform/source_patches.py` 在僵尸第一次实际更新、完整存档恢复后，对零速率调用原游戏 `UpdateAnimSpeed()`，重新计算派生状态。已有非零速率保持不变，冰冻、黄油和死亡阶段仍使用原规则；不修改移动速度、动画时间、随机数或存档格式。

## 验证结果

- 主机完整游戏回归通过：600 次更新、动画与画面变化、选项暂停／恢复、零速率存档继续，以及黄油状态读档后仍保持停止。
- H1 原第一关存档中的 4 个停住僵尸恢复活动；3 个同 ID 僵尸的坐标、动画时间和年龄变化已记录，随后剩余僵尸被植物正常消灭。
- 在 H1 实际通过新建玩家对话框输入 `Zzz`，完成开场，进入全新的第一关。通过触摸种植、收集阳光再种植，自然生成第一只僵尸；坐标由 777.09 变为 758.83，动画时间由 0.077 变为 0.502，速率为 14.46。截图可见两棵豌豆射手和豌豆子弹。没有写入游戏 RAM 制造成功结果，也没有使用预制玩家存档代替这次新建操作。
- 正常退出返回 0，后台存档任务结束，写入错误和队列占用均为 0，工作任务删除，原中断回调恢复。
- 整个原 `userdata` 目录已切回，原 6 个文件逐一回读并与测试前 SHA-256 比对一致；测试数据另行归档。调试器保持运行，电脑串口已关闭。

安装到 H1 和本地 `prebuilt` 的程序完全一致，大小 3,752,692 字节，SHA-256 为 `dedbe8f8807ced1cd68eba1e6ec7cf4a96294054f72d6e38c1fae716fd27345b`。设备端上传 CRC、GP/TLS 审计和直接平台源码身份检查通过。资源未变更。

具体证据、截图和范围见 [真机汇总](verification/zombie-motion-20261113/results.json)。原始请求、回执和串口记录在本地 `build/zombie-motion-v77-hardware/`。
