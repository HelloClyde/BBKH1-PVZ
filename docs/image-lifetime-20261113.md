# 图片与动画数据生命周期（2026-11-13）

图片像素由实际场景、控件、动画、粒子系统和拖尾持有。共享图片只有一份像素，最后一个使用者结束就释放。场景切换结束旧场景的引用；通用选项素材由交互界面共享，非交互开场期间释放，下一关加载时预载，退出应用全部释放。删除图片 LRU、大小预算及分配失败触发的图片回收，分配器只整理完全空闲的内存页。

菜单离线画面原先在退出菜单时只解除绑定，约1.6MB等待内存紧张才回收；现在菜单结束即全部释放。动画解码器清掉 Loading 中未使用的预留页，并在一套动画不再参与绘制时释放其工作页。仍在播放的同类动画共用数据，避免每帧重新解码。文字与绘图计算结果仍有场景内复用，随所属图片或场景结束清理。

真机使用相同的40株植物、第六关原生V4存档，经正常触摸继续游戏、三次选项、240秒后续游戏和返回菜单。旧版短采样约13.45FPS，候选约12.54FPS；选项首次呈现为[75, 50, 50]ms。此次解决资源释放和内存稳定性，不宣称达到20FPS。关卡内菜单离线画面占用0B，回菜单后图片像素占用749272B；图片自动驱逐次数0。

同一进程随后通过真实UI新建Lll、Mmm，两次播放348帧开场文件并在13,890ms自然进入第一关，均无运行时内存分配失败。实际逐帧解码计数保留在验证记录中，受LCD呈现节拍影响，最后一帧不保证都被显示。正常退出后，图片引用、像素、动画数据及后台保存队列均清空，保存任务退出、原IRQ回调恢复。原用户目录整体恢复，六个文件逐一比对大小与SHA256通过。H1Debug仍驻留，电脑串口已关闭。

主机验证包含共享图片最后引用释放、真实对象死亡/隐藏、自然结束的开场、40株植物重复画面对照、弹窗、菜单57组整屏像素对照和六种草坪。未受相关改动影响的既有草坪与菜单对照结果复用。测试覆盖范围和原始结果见[验证记录](verification/image-lifetime-20261113/results.json)。构建194个源文件，GP/TLS审计通过，BDA与H1上传CRC匹配。

早期实验曾因菜单驻留和解码工作页占用触发内存不足；逐帧释放解码页虽通过长时间测试，但降到约9.94FPS，未采用。最终采用共享动画数据的生命周期。完整模式、所有关卡和长期数小时运行未做全量复测。资源文件未修改，未推送或发布新版。
