# H1 离线动画与缓存生命周期

这轮修改解决离线资源加载失败后继续使用旧绘制路径、植物预览临时生成大画布，以及已经结束的阶段仍占用动画缓存的问题。游戏继续编译原有逻辑和动画时钟，成品身份与物理 H1 结果见 [最终真机记录](verification/final-native-verification.json)。

## 内存问题与处理

真机曾有约 640 KB 总空闲空间，但最大连续空闲块只有 63,228 字节，16 号描边字体申请 63,284 字节时失败。随后还定位到 `ReanimatorCache::MakeBlankMemoryImage(120,120)`：卡片预览仍在设备上申请 57,604 字节并绘制植物。

- 植物、割草机、僵尸预览共 214 个合法工厂键全部离线生成。保留原逻辑尺寸，存储尺寸分别为约 54×54、41×45、91×95；设备读取至最多 4 KB 的页，不再生成原预览画布。
- 原预览画布工厂和预览光栅函数在 H1 构建中排除。ELF 符号检查与原工厂 API 的整合测试都确认了这一点；主机仍可使用原工厂生成和核对素材。
- RGBA 图集从 1,024 像素起分页，每块最多 4 KB；A8 图集从 1,024 字节起分页，每块最多 1 KB。中文继续使用已有离线字形包。
- 必需的预览、植物帧、阶段动画、草坪在加载阶段检查失败并报告错误，不因失败而悄悄恢复旧光栅绘制。

## 资源生命周期

混合角色包拆成豌豆过渡、僵尸受击、铺草三个阶段包；普通动作的 211 条重复记录移入独立普通帧包。3,837 条原记录的完整覆盖与像素包一致性由验证器检查，旧混合包只作为构建输入保存。

铺草结束后释放铺草帧。原动画实例删除时清除其签名、帧时间和活跃轨道记录；原定义释放时清除其基准矩阵记录。进入关卡前，先确认菜单定义已没有实例引用，再释放它；回菜单、换关和退出时释放相应的帧与预览所有者。

本关后续仍会使用的公共帧保持预加载，避免下一次出现植物或僵尸时重新读盘。上一关不再需要的类型和颜色变体会在新关加载前移除。缓存释放不改变动画对象、事件时间或 V4 存档内容。

## 绘制与退出

完整植物包包含 50 种动画，含原色在内四种滤色状态，共 200 组帧数据；共享几何与调色板组件减少重复存储。普通帧采用预计算 LCD 偏移的直接像素数据。六种普通草坪按 480×272 屏幕行顺序离线排好，重绘时合并连续区域拷贝；池水等动态覆盖层保留原逻辑。屏幕提交一次比较后只写变化的 RGB 像素。

活跃轨道索引省去无混合、无抖动、无附件的空更新遍历；原时钟、随机数消耗、混合、眨眼和附件更新由完整原引擎定向对比。相等端点插值、零倾斜矩阵和帧时间查询使用精确数值优化。

退出仍走原存档策略：回菜单、退出、关卡结束时保存。相同文件先完整比较并核对 EOF、关闭结果，避免重复写入；数据不同或比较失败时仍走原事务写入。普通日志进入有界 RAM 环，减少额外写盘。

## 验证边界

[主机专项证据](verification/exit-plants-host-verification.json)保存了像素、动画更新、失败清理、存档故障与写入桥接检查的身份。完整固件检查和物理设备结果分别记录；固件模拟器不用于证明真实帧率或 B 盘行为。

性能使用真实 40 Hz 设备时钟和实际显示帧计数，固定输入为原游戏 API 生成的第六关 40 株植物存档。未向运行中的游戏写入帧数、分数或成功状态。测试结束读取设备写出的 V4 文件，核对原格式长度和 CRC，再逐字节恢复原用户文件并移除测试存档。

仍有部分动态缩放等视觉状态没有完全烘焙；本轮不宣称所有状态已经全离线，也不把主机通过或模拟器流畅当作达到 20 FPS。

运行资源共 2,755 个文件、139,832,497 字节。新增完整植物帧和预览后资源体积增加，运行时按当前关卡选择加载。程序与完整资源一起更新，并保留 `userdata/`；构建输入不复制到 H1。
