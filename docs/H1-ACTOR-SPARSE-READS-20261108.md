# 离线动画随机页读取

候选 v20 的完整 BDA SHA256：
701cb3f8a89f0dbc2899046dcca735ca46678f0fa6b08c8f0e71bcee0d8d08a3。
v20 已完成真机验收；本轮后续候选仍在测量，不能据主机结果声称达到 20 FPS。

复用 v19 同一第 50 关输入记录后发现：100 个绘制帧期间，图片缓存加载
次数 1013、驱逐次数 635、载入像素字节 8664340 均未变化，然而底层
读取仍请求 9,380,864 字节，读取耗时累计 109 个 40 Hz tick。
离线动画页未命中增加 652、命中增加 18,760。
pvzh1_actor_page_diagnostic[3] 是命中次数，不是读取字节数。

原动画文件用 16 KiB stdio 缓冲。稀疏访问的压缩页最多 4128 字节，
每次 fseek 后的 fread 经常再次填充完整 16 KiB 缓冲。v20 保留顺序
元数据加载的缓冲；开始实际随机页访问后同步并退掉缓冲，用该文件
自己的 fd 定位并读取所需页。原文件仍由原 FILE 统一关闭。短读正常
聚合，失败仍报告实际 I/O 错误；没有增加原绘图路径或动画资源。

新增按动画类型计数的页命中、未命中、文件读取次数和字节，用于判断
后续应调整哪个缓存，避免按全局最后一次加载的银行大小猜测。
这些计数只统计实际重放，预加载不计入。

定向主机验证通过：实际普通僵尸及闪光的 36 组整屏像素比较一致；
强制仅 2 个解码槽，独立 stdio 文件句柄逐次核对 18,268 次随机读取，
共 41,874,201 字节，最大单次请求 3535 字节，全部一致。
另通过原关卡资源生命周期测试，退出时缓存占用归零。
相关证据在 build/actor-sparse-io-host-v20-fixed 和
build/actor-sparse-lifetime-host-v20。

真机驱动位于 build/actor-sparse-v20-hardware/test_device.py。
使用原存档副本构造第 50 关前置输入，原目录保护名为
userdata.before-sparse-v20-20261108；收尾必须正常退出并整体恢复原目录，
再读回两份原始资料核对。运行资源及旧的失败遮罩修复不变。

## 2026-11-09 后续实测

相同第 50 关资料副本和进入步骤，早期战斗窗口 v19 约 9.06 FPS，
v20 约 11.64 FPS。快照之间底层请求读取从 9,380,864 字节降至
907,877 字节，读取计时从 2,725 ms 降至 325 ms；各窗口分别覆盖
100 和 135 个呈现帧，不能把这个字节比例直接当成帧率比例。
v20 的最后一帧图片缓存加载次数仍未增加。新分项计数显示花盆没有
解码页缺失，普通僵尸仍有少量新姿态页读取，因此没有扩大所有缓存。

v21 把已经缩小的纹理的安全整段 UV 采样扩展到旋转图形。保持原最近邻
采样、alpha 阈值和整数合成取整；跨边界的 UV 仍由原采样器逐点处理。
主机 303 组采样与 88 组实际 Boss 画面逐像素一致，包含分页纹理。
真机旋转快速路径处理约 621 万像素；Boss 包含计时约 19 ms/帧，
之前约 23 ms/帧，但整体 FPS 11.47，不能声称整场明显提速。

v22 只使用 2,048 字节固定静态空间复用相同 float 角度的 libm 结果，
不量化角度、不改变动画时间。原公式矩阵 63,153 次比较逐位一致，
包含 55,953 个真实 Boss 变换和非有限值／正负零／极端缩放。
整屏画面对比继续通过。真机约 11.37 FPS，没有整体提速证据。

v20～v22 原生音乐模块每次均一次加载成功，播放器计数为 1，
堆申请失败记录为全 0；选项弹窗的字体整图请求记录也全 0。
这只是这些实际窗口的结论，不能推成所有关卡已全部验收。

v23 实验仅把 Board.cpp、Plant.cpp、Zombie.cpp 改为定向 O2，
其余仍按原构建设置。完整程序增加约 100 KB，ELF code/data/bss
合计 4,086,753 字节，通过固定装载地址上界链接检查。尚待真机结果
决定是否纳入正常构建。

本阶段没有增加任何动画或图片资源；资源包尺寸不变。候选 FPS 只采
原生 40 Hz tick 与实际呈现帧，不把主机速度或指令减少等同真机提速。
进入战斗后自然随机出怪／动作时点会有变化，小幅差异不能据此判定收益。
压缩证据归档：docs/verification/actor-sparse-render-20261109/performance.json。
旧 test_fast3.py 的观察器入口已经过时，固定字符串断言失败，未运行
其业务矩阵；改用当前完整引擎入口的独立原公式矩阵对比和实际 Boss
整屏对比验证本轮受影响行为，未把该旧脚本称为通过。

后续 v24 首个战斗窗口约 13.67 FPS，音乐一次加载成功、播放器 1、
打开选项约 100 ms。但接着 30 秒更密集场景只有约 8.39 FPS，不能
把初段结果推成整场速度。普通僵尸离线页未命中增加 1826，读约 5.9 MB；
这是选择只提高僵尸解码页上限的依据，不是扩大所有素材缓存。

v24 随后打开选项／回主菜单期间又出现 std::bad_alloc 并异常返回 12。
申请 1,000,156 字节时总空闲 3,277,972 字节，最大连续块 281,696 字节。
调用点位于 MemoryImage::GetBits，尚不能仅凭此认定是文件分辨率或某个
具体调用方。新增所有大图 GetBits 的路径／调用点记录，v26 正在复测。
v24 不应作为通过版本或公开发布。原目录仍整体保护，尚未恢复。
