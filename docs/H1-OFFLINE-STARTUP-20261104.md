# 启动、冒险入场与音频供给优化

这轮保留完整冒险入场动作、450 次原版更新、按钮闪烁、破土声和怪笑。动作更新、继续存档、新关卡与特殊关卡分支仍由原版代码控制。

## 离线数据

- 20 个字体描述编译为 `.h1fc`，直接建立字形、字距、图层、标签及文字定义；共享中文字表保持按需展开。导出使用原版解析器并对所有序列化字段做往返比较。真机启动使用其中 18 个字体。
- 169 份音频文件的头信息合并为 `sounds/index.h1si`，避免为每个音效单独打开文件读取头部。
- 原版标题音乐从 XM 的 order 152 开始，以同一 libxmp 配置离线渲染为 87.2 秒、16 kHz 单声道 PCM。整个第一循环与原流式播放 API 逐样本相同；标题音乐提前放入堆内存，游戏音乐保留原版调度及动态声部。
- 107 份粒子/轨迹 `.h1d` 合并为 29,418 字节的包，一次顺序读取。包中每份数据与此前验证的单独文件字节相同，并分别检查 CRC。
- 冒险手部动画保存 114 个采样姿态，另含 6 个按钮灰色闪烁状态。采样率 25 FPS；完整原版动画仍按 100 Hz 更新。文件约 2.9 MB，进入菜单时解压并加载到堆内存，绘制时直接重放最终像素片段，不再计算矩阵、纹理坐标或重新采样。342 组整帧检查与原版渲染器一致。

移除了 H1 不使用的原版编译缓存扫描：原代码会为 146 个动画查询两处旧缓存位置。H1D 仍按需加载，不因启动而预载所有关卡。

## 绘制和声音

原来的菜单缓存判断把“开始冒险”当成回退条件，点击后整张菜单恢复成较慢的原始绘制。这一限制已移除；背景和按钮继续使用离线像素，手部动作使用预渲染帧。异常姿态、裁剪或滤镜仍可回退原绘制。

音频环形缓冲位于堆上。正常交互维持较短缓冲，阻塞加载前提前补足；加载期间按实际缺口补充全部音频，避免多次长任务之间只补 128 ms 而逐渐耗尽。文件读取、定义解码、菜单缓存准备和绘制边界会协作供给音频，并有递归保护，所有文件操作仍在同一前台任务上完成。

XM 的扫描、轨道去重/释放和 V4 存档字段同步也有协作点；原生读取按 16 KiB、写入按 4 KiB 分块，在 SDK 调用返回后供给音频。没有活动声音时先排完真实尾音，再停止空描述符；下一段声音重新启动输出，避免静音加载时让旧片段绕环重复。音频回归检查保持原 PCM、order/row、速度、BPM 与循环计数一致，读写检查保持文件内容与短读、短写行为。

冒险动画的三段音效提前缓存；菜单绘制数据在创建关卡前释放。返回菜单播放标题音乐时释放已经停止的 XM 模块，再申请标题 PCM，限制瞬时内存峰值。

返回菜单在写配置、销毁关卡之前进入加载供给阶段，覆盖原先存档函数返回后留下的空档。退出也在停止音乐和音效后排完已提交的尾音，再销毁应用资源。普通音乐切换保持即时返回；音频没有活动生产者时，播放完最后一块后进入零填充区域属于正常结束，仍保留完整绕环和活动生产者断供的独立检查。

原版保存使用资源指针反查 ID 的树形缓存，每次重建需要大量独立节点分配。H1 改为一份连续的排序数组，保留相同指针取最后一个 ID 的原规则；20 次重建、220,020 次比对与原实现一致，包含别名、空指针和未知指针。静音重载前若还有已排入输出的真实尾音，会先排完尾音再开始长任务。
