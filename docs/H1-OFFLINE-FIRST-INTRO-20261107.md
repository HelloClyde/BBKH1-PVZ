# 首次新玩家开场的离线处理

原版新玩家开场创建 28 株植物、16 只僵尸，执行战斗更新，再逐帧绘制动画、投射物、变换、闪白、字幕和淡出。旧版物理 H1 固定输入测得 168 帧 / 3,133 个 40 Hz tick，即 2.14 FPS；绘制占 2,188 tick，更新占 837 tick。基线绑定到 `abb3d838…18417e`，见验证目录的 `baseline.json`。

现在由 PC 调用原版完整逻辑及中文、宽屏绘图代码，固定随机种子，按 40 毫秒间隔导出完整 480×272 画面。保留原来的 13,890 毫秒时间轴、音乐、音效及自然进入第一关的回调。348 帧包括字幕、横移、战斗、闪白和淡出；没有跳过开场。黑幕和字幕均覆盖完整宽屏。

## 格式与内存

资源 `first-intro.h1if` 为 12,934,438 字节。颜色在电脑上转换为 RGB565，横向位移也在电脑上搜索，然后存储相邻帧的异或差分及 LZ4 块。除离线颜色量化外没有进一步有损压缩。H1 只解包、按已知位移还原像素，通过两张离线生成的 256 项小表直接写入原生屏幕。参考 PAL3 的 RGB565 提交方式，去掉先生成 32 位整图、再复制到 LCD 的两次整屏处理；没有原开场的装饰战斗、骨骼变换或混合绘图。暂停或对话框需要叠加时仍使用同一份离线画面。

进入开场前校验完整资源 CRC，保留 9 MiB 顺序预读，预读接近耗尽时才补充，减少滚动期间的读卡。预读由 36 块 256 KiB 普通堆内存组成，可复用已消费的空间；其余工作缓冲和元数据使峰值请求量为 10,290,256 字节。测试曾出现总空闲约 12.3 MB、最大连续块只有约 3.3 MB 的情况，故采用分块申请，避免要求一块大连续内存。它属于当前 Board，进入实际关卡前完整释放。资源缺失或损坏会明确报错。PC 素材生成器才显式关闭回放以导出原始画面。

开场音乐仍使用原 XM 事件、通道及采样。离线副本 `mainmusic-intro.xm` 仅保留原开场入口 `0x5e` 所需的数据，采样从 5,014,597 字节减至 2,602,527 字节；图案和乐器编号不变。只在新玩家开场选择该副本，正常泳池和其他关卡沿用完整模块。对原始入口播放、30 通道音量变化及 7,251,440 个样本的比较逐样本一致，不声称任意歌曲位置跳转都可用精简副本。

开场只推进原 CutScene 时钟、音乐和音效，停止已被影片替代的战场更新和闪白粒子创建。巨大浪潮、警报两个音效共 325,116 字节，在播放前缓存；实际关卡继续准备完整音效，播放器的混音、音量和时间调度没有替换。

## 真机结果（2026-11-08）

程序 `f74f2f0a…1dc1cc` 在物理 H1 上完整开场约 23 FPS：14,000 毫秒内实际输出 322 个不同帧索引。持续滚动段 114 帧 / 182 个原始 tick，即 25.05 FPS；原始时钟为 40 Hz。计数发生在原生 LCD 写入完成后，重复画面提交不重复计帧；采样阶段结束后才下载截图。原 CutScene 在 13,890 毫秒自然触发进入第一关，未跳过开场。

滚动采样期间没有补读视频数据，音频欠载计数未增加；原 XM 播放器持续活动，两个音效均已缓存。整个开场的声音是否零欠载不由这个局部采样单独认证。真机截图与独立验证回放的第 265 帧 RGB 像素完全一致。

实际第一关触摸种植、僵尸、子弹及选项均正常；回菜单后从 B 盘读回 47,752 字节 V4，头、载荷长度和 CRC 正确。正常退出后游戏堆和原生记账归零，原用户文件逐字节恢复，临时测试资源删除，H1Debug 保持运行。没有重测当前 BDA 的密集植物场景，也未重跑完整四波通关；旧版记录分别保留，不能当作本版重测。当前总证据入口为 `docs/verification/final-native-verification.json`。

## 验证边界

主机完整游戏自然播放 348 帧并进入第一关可玩状态，实际输出逐帧与独立 RGB565 量化结果比较，全部一致；同时检查重复帧复用、已消费缓存复用、装饰对象不创建及缓存释放。C 解码器另有边界、重叠拷贝、损坏输入、七种位移、全部 65,536 种颜色和完整影片测试；原生直接提交核的每一种颜色也逐一比较。主机验证不代替真机帧率。

按用户建议参考了 PAL3 的 tinyh264/h264bsd 代码，也做了物理 H1 对比。此次测试的纯 C H.264 路径在完整游戏滚动段约 4.8 次实际绘制/秒；单独测试 16 帧解码、转换和复制平均约 79.7 毫秒/帧，全 O2 仍同档。没有测 PAL3 的 MXU 优化，也没有修改 CPU 频率，因此这些结果只代表所测纯 C 实现。H.264 参考代码放在 `vendor/tinyh264`，保留原许可和来源，最终 BDA 不链接它。

## 重建

```powershell
python -m pip install -r requirements-build.txt
python tools/bake_first_intro.py export
python tools/bake_first_intro.py encode
python tools/bake_file_index.py
python tools/bake_first_intro.py verify --build-dir build/first-intro-frames-playback
python tools/verify_intro_movie.py
python -m unittest discover -s tools/tests -p test_intro_frames.py
```

需要完整主机构建和 UCRT64 GCC；原生格式生成使用固定版本 lz4，不需要 FFmpeg。仅可选的 `encode-h264` 对比需要 FFmpeg/libx264。资源与生成器哈希见 `provenance/offline-first-intro.json` 和 `provenance/offline-intro-music.json`。H1Debug 负责完整 BDA/资源上传、普通触摸输入及只读采样，没有写入游戏 RAM 设置进度。
