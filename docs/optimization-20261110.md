# H1 密集场景优化：2026-11-10

本轮完成离线状态补齐、重复色表共享，以及植物颜色和僵尸／阳光无作用轨道的重复工作消除。真机仍为 **6.49 FPS**，与 V62 相同，未达到 20 FPS；不能把本轮称为整体提速通过。

## 实现和边界

- 离线补齐：650 个眨眼拉伸采样、1,911 个阳光缩放采样、1,023 个普通僵尸走路转啃咬采样。转场显示采样 50 Hz，原有 20 次逻辑更新全部保留；包含 25 档受击闪白和帽子破损状态。少量二维拉伸眨眼、walk2 过渡等未选状态仍走实时绘制。
- 新转场的 3,216 组颜色全部与已有僵尸／帽子色表一致。离线生成 6,432 字节索引，替代内存中的 334,464 字节重复表，净省 328,032 字节；游戏不比较、不生成、不校验颜色表。
- 植物颜色未变化时不重复递归传递；新挂上的眨眼附件仍立即同步。普通僵尸和阳光也使用活跃轨道列表，保留混合计数、震动、附件更新、动画时钟和随机数顺序。
- 资源包 169,682,048 字节，约 161.82 MiB，2,674 个文件。V64 已传的三个大包未变化并复用传输凭据；最终只更新程序、色表索引和目录索引。

## 内存诊断

V64 捕获的第一次失败申请为用户 3,072 字节、原始 3,103 字节。当时共享堆总空闲 148,952 字节，最大连续块／尾部 66,076 字节；尾部分配还受 65,536 字节原生 SDK 预留限制，其他空洞不足以满足请求。存在接近容量上限、碎片和预留策略共同作用，不能简单归咎于素材分辨率，也不是最终 OOM。

原生共享堆为 32 MiB。失败时游戏受跟踪的原始分配约 22.57 MB，其余约 10.8 MB 为未纳入此统计的原生分配。游戏正常退出后仍有 9,799,948 字节原生分配存在，不能把这些块当成游戏动画缓存释放。完整描述符和分配链盘点位于 build/replay-v64-hardware。

相同存档的测试区间，捕获的初始申请失败从 V64 的 275 次降至 V66 的 112 次，最终分配失败均为 0。这里的区间包含继续关卡和暂停两端操作，宽于无调试 RPC 的纯测速窗口。

## 验证

- 眨眼／阳光：1,042 次实际渲染回放与采样后原着色器整帧比较通过，模拟矩阵原位比特不变。
- 僵尸转场：共享颜色表前后各 3,200 次整帧比较通过，原动画时钟不变。
- 颜色传递：300 份状态／随机数比较，10 次持续高亮期间新眨眼挂接通过。
- 僵尸／阳光：每条路径 700 次真实动画更新，4,200 份状态、帧时间、随机数观察一致；定向试验省掉 182,733 次无作用轨道扫描。
- 原生编译、固定窗口大小及 GP／TLS 审计通过。最终候选 SHA256：`ae6b44d12720d061ad37139aba72600cac6c9139a32f3a39f5c0c39e1cd283d8`。
- 真机粗计时：99 帧／610 个 40 Hz 原始 tick＝15.25 秒＝6.49 FPS，窗口内无调试 RPC。固定输入为 45 株植物、5 个路障僵尸、初始关卡计数 226 的同一份存档。

细分计时另开同样存档、启用全量归因：绘制约 99.5 ms／次、逻辑更新约 47.7 ms／次绘制；其中动画包页面约 31.4 ms、包头／分段准备约 26.8 ms、像素回放约 28.1 ms。**这些计时相互嵌套，不能相加，也不能与粗计时直接视为同一次采样。** 剩余主要问题已转为离线包的运行时取页、解压和包准备，增加烘焙状态本身没有解决这个瓶颈。

完整仓库校验未通过：在进入本轮素材检查前，旧 preferred-alpha 元数据中的 platform/graphics/memory_patches.py 源码指纹已过期；没有修改旧证明去掩盖这一失败。本轮改动资源的指纹、480×272 头、目录索引及 Python 工具编译定向检查通过。

原存档已整目录恢复，users.dat 与 user1.dat 回读 SHA256 均与测试前备份一致。游戏正常退出，串口控制会话已关闭；新程序和资源保留在 H1，调试驻留服务保持开启。

本轮原始着色器采样临时文件已清理，回收 2.40 GiB；源码、最终资源、真机日志与验证证明保留。
